# dgo v1.2.0

This minor release raises the minimum Go version to 1.27.4 and makes the REST
error types implement `error` only through their pointer types. It adds no new
Discord API surface. The REST error change is source-incompatible for code
that uses the value types `RESTError` or `RateLimitError` as errors; see
[REST error types](#rest-error-types) before upgrading.

## Upgrade

```sh
go get github.com/darui3018823/dgo@v1.2.0
go mod tidy
```

Go **1.27.4 or newer** is required. Review the
[migration guide](https://github.com/darui3018823/dgo/blob/v1.2.0/docs/Migration.md)
when upgrading from v1.1.0.

## Go 1.27.4 minimum

- The root module and the `linked_roles` and `voice_receive` example modules
  now declare `go 1.27.4`.
- Go 1.27.4 fixes
  [CVE-2026-97040](https://pkg.go.dev/vuln/GO-2026-6851), a cgo directive
  injection through `.syso` files in `cmd/go` and `cmd/link`, and
  [GO-2026-6859](https://pkg.go.dev/vuln/GO-2026-6859) (CVE-2026-97054), an
  HTTP/1 server crash in `net/http`. Both are toolchain and standard library fixes: applications
  receive them by building with Go 1.27.4 or newer, whichever dgo version they
  use.

## REST error types

- `RESTError` and `RateLimitError` now implement `error` (and
  `RESTError.Unwrap`) only as `*RESTError` and `*RateLimitError`. Go 1.27
  `go vet` rejects wrapping them with `%w` while their methods use value
  receivers.
- dgo has always returned these errors as pointers, so matching them with
  `errors.As` and a pointer target needs no change:

  ```go
  var restErr *dgo.RESTError
  if errors.As(err, &restErr) {
      // ...
  }
  ```

- Code that used the value types `RESTError` or `RateLimitError` as an `error`
  must switch to the pointer types. This includes returning, assigning, or
  type-switching on the value types, which no longer compiles.
- `errors.As` with a value target, such as `var v dgo.RESTError;
  errors.As(err, &v)`, still compiles but now panics at run time with
  `errors: *target must be interface or implement error`. In v1.1.0 it
  silently returned `false`. `go vet` reports these call sites; run it before
  upgrading and change the target to a pointer type as shown above.

## Verification

The release is verified with root and standalone example-module tests and vet.
The full CI workflow remains the release gate for race detection, coverage,
static analysis (staticcheck 2026.2.2), vulnerability scanning (govulncheck
v1.10.0), and the strict MkDocs build.
